# Quinsy Studio — Anti-Slop Audit

> AI-generated code has characteristic patterns that make it worse than manually written code.
> The anti-slop audit detects and prevents these patterns.

## What is AI slop?

AI slop is code patterns that are typically generated by LLMs and degrade code quality:

```
- Redundant variables and imports
- Overly verbose functions
- Generic error handling (catch-all)
- Missing specific error messages
- Over-commented code
- Unused parameters
- Redundant logic
- Missing edge-case handling
- "Helper" functions that are never called
```

## Audit rules

### Category 1: Code slop

| Rule | Description | Severity |
|------|-------------|----------|
| S1 | Unused imports | Warning |
| S2 | Unused variables | Warning |
| S3 | Dead code (unreachable code) | Error |
| S4 | Redundant functions (never called) | Error |
| S5 | Redundant conditions | Warning |
| S6 | Unused function parameters | Warning |
| S7 | Excessive nesting (>4 levels) | Warning |
| S8 | Magic numbers `100` / `1000` / `86400` without unit suffix | Error (regex gate) |
| S9 | Sequential `await fn();` on consecutive lines | Error (regex gate) |

### Magic numbers & sequential awaits (LO-0029)

`validate_anti_slop.py` flags bare `100` / `1000` / `86400` (unless followed by `ms`/`px`/`%`/`rem`) and two consecutive `await call();` lines. These are **not** false positives to soft-disable mid-sprint — fix project code:

1. **Named constants** — e.g. `const JPEG_QUALITY_PERCENT = 100` or `MAX_PNG_BYTES_BEFORE_JPEG = 1000 * 1000` (name carries the unit).
2. **Sequential awaits** — chain (`await apply().then(...)` is fine) or extract `async function exportPdfPipeline(...)` so the gate does not see `await;\nawait`. Independent work should use `Promise.all` when order does not matter.
3. **Tests** — same rules apply to `*.test.ts`; do not rely on test-file exemptions. Prefer named constants in fixtures too.
4. **Ticket DoD** — if export/PDF work touches these paths, include “anti-slop green on changed files” so mid-gate thrash does not block review.

### Category 2: Comment slop

| Rule | Description | Severity |
|------|-------------|----------|
| C1 | AI-typical comments ("This function does X") | Warning |
| C2 | TODO comments without owner/date | Info |
| C3 | Commented-out code | Warning |
| C4 | Over-commented trivial functions | Warning |

### Category 3: Error-handling slop

| Rule | Description | Severity |
|------|-------------|----------|
| E1 | Catch-all without specific handling | Error |
| E2 | Missing error handling | Error |
| E3 | Swallowed errors (catch without logging/throw) | Error |
| E4 | Generic error messages | Warning |

### Category 4: Architectural slop

| Rule | Description | Severity |
|------|-------------|----------|
| A1 | Missing abstraction layers | Warning |
| A2 | Circular dependencies | Error |
| A3 | God functions (>100 lines) | Warning |
| A4 | Missing typing (any/unknown) | Warning |
| A5 | Inconsistent naming | Warning |

### Category 5b: UI / mock slop (design + FE)

Canonical playbook: [anti-slop-design-ux.md](../knowledge-base/anti-slop-design-ux.md) (Team 10 + agents).

| Rule | Description | Severity |
|------|-------------|----------|
| U-D5 | Emoji-as-icon in product UI or mocks (LO-0037) | Error (review) |
| U-D1 | Decorative blobs / purposeless glassmorphism | Error (design review) |
| U-D3 | Broken grid / unanchored padding | Warning |
| U-C2 | Generic SaaS-blue template ignoring brand DNA | Warning |
| U-T2 | Marketing hero scale on operational dashboards | Warning |
| U-P1 | `Lorem ipsum`, `Feature 1`, `Primary action` in mocks/UI copy | Warning (automated) |

- Design specs: `design-system-compliance-checklist.md` + `anti-slop-design-ux.md` must pass before `approve-design`.

### Category 5c: Copy / microcopy slop

| Rule | Description | Severity |
|------|-------------|----------|
| M1 | Banned fluff vocabulary (supercharge, seamless, unlock, delight, ecosystem, …) | Warning (automated in `.md`, `.tsx`, `.jsx`, `.html`) |
| M2 | Non-literal CTAs (`Proceed`, `Let's go`, `Make magic happen`) | Warning (review) |
| M3 | Conversational agent filler in specs | Warning |

Full banned list: [anti-slop-design-ux.md §2.1](../knowledge-base/anti-slop-design-ux.md).

### Category 5: Dependency slop

| Rule | Description | Severity |
|------|-------------|----------|
| D1 | Unused dependencies | Warning |
| D2 | Duplicate dependencies | Error |
| D3 | Deprecated dependencies | Warning |
| D4 | Overly broad dependencies | Info |

## Audit tool

```bash
# Full anti-slop audit
./studio gate <project> --anti-slop

# Only a specific category
./studio gate <project> --anti-slop --category code
./studio gate <project> --anti-slop --category comments

# Output as JSON (for CI/CD)
./studio gate <project> --anti-slop --json
```

## Prevention strategies

### For agents/copilot

```markdown
## Prompt engineering against slop

1. Give specific instructions
   ❌ "Write a function that does X"
   ✅ "Write a function that does X, with error handling for Y and Z"

2. Demand a code review
   ❌ "Write the code"
   ✅ "Write the code and then check it for AI slop patterns"

3. Name best practices
   ❌ (no constraints)
   ✅ "Use specific error messages, avoid catch-all"
```

### For reviews

```markdown
## Code review checklist against slop

- [ ] Are all imports used?
- [ ] Are all variables used?
- [ ] Is there unreachable code?
- [ ] Are there redundant functions?
- [ ] Are errors handled specifically?
- [ ] Are comments informative (not trivial)?
- [ ] Are functions not too long (<100 lines)?
```

## Integration with gates

The anti-slop audit is a **mandatory part** of gate 5 (QA gate):

```bash
./studio gate <project> --level 5
# Runs the anti-slop audit automatically
```

**Rule:** a gate cannot be green if the anti-slop audit has error violations.
